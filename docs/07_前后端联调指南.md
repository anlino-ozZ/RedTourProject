# 07 前后端联调指南

> 联调模式：**每人本地各搞一套**（数据库 + 后端 + 自己的前端），前端通过 `.env.development` 指向后端地址。
> 配套阅读：`docs/06_开发环境搭建清单.md`、`docs/05_全局接口精简文档.md`。

## 一、联调模式总览

### 1.1 两种联调方式

| 方式 | 前端连谁 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 本地自给自足**（推荐） | 自己本机后端 `localhost:8000` | 数据可控、不依赖他人 | 前端也要装 MySQL+Redis+后端 |
| **B. 指向他人后端** | 某个后端同学的局域网 IP | 前端免装数据库 | 依赖对方开机、共享一套数据 |

### 1.2 数据流

```
前端 dev server (5173/5174/5175)
       │ Axios HTTP
       ▼
后端 server-business (8000)
       │ HTTP                 │ TCP
       ▼                      ▼
ai-engine (8001)        hardware-rpi (9000)
       │
       ▼
Ollama (11434) + MySQL (3306) + Redis (6379)
```

## 二、后端同学准备（YYJ / YST）

### 2.1 完成本机后端启动

参照 `docs/06_开发环境搭建清单.md` 第四章：

```bash
# 1. 装好 MySQL + Redis，执行 schema.sql
mysql -u root -p < packages/server-business/src/main/resources/db/schema.sql

# 2. 改 application-dev.yml 的数据库密码

# 3. 启动后端
cd packages/server-business
mvn -s G:\settings\settings.xml spring-boot:run
```

### 2.2 自检后端可用

```bash
# 健康检查
curl http://localhost:8000/api/v1/health
# {"code":0,"message":"ok","data":{"db":"ok","redis":"ok","ai":"unavailable","hardware":"offline"}}

# 登录
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# 返回 token 即可
```

### 2.3 对外联调：开放局域网访问

如果要让前端同学通过方式 B 联调，需：

1. **确认本机 IP**：`ipconfig`（Windows），记下 `192.168.x.x`
2. **后端默认 `0.0.0.0:8000`**：[application.yml](../packages/server-business/src/main/resources/application.yml) 已配 `host: 0.0.0.0`，局域网可访问
3. **防火墙放行 8000 端口**：
   ```powershell
   # Windows PowerShell（管理员）
   New-NetFirewallRule -DisplayName "RedTour-Backend-8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
   ```
4. **告知前端同学你的 IP**，让他们改 `.env.development`
5. **保持后端常开**，关机前提醒前端同学

## 三、前端同学准备（ZAL / MPH / NJY）

### 3.1 方式 A：自给自足（推荐）

前端同学本机也装后端栈，独立联调：

1. 按 `docs/06_开发环境搭建清单.md` 第四章装 MySQL + Redis + JDK + Maven
2. 执行 schema.sql 灌测试数据
3. 启动后端：`mvn spring-boot:run`
4. 启动前端：`npm run dev`
5. `.env.development` 保持默认 `localhost:8000`

### 3.2 方式 B：指向他人后端

```bash
# 编辑你负责前端目录的 .env.development
# packages/web-h5/.env.development
# packages/web-admin/.env.development
# packages/web-touch/.env.development

VITE_API_BASE_URL=http://192.168.x.x:8000/api/v1
#                            ↑ 改成后端同学的局域网 IP
```

改完后**重启 dev server**（Vite 不会热加载 env 文件）：

```bash
# Ctrl+C 停掉，再重启
npm run dev
```

### 3.3 验证联调通路

浏览器 F12 控制台执行：

```javascript
fetch(`${import.meta.env.VITE_API_BASE_URL}/health`)
  .then(r => r.json())
  .then(console.log)
```

返回 `{code:0, message:"ok", data:{...}}` 即通。

## 四、接口路径与鉴权约定

### 4.1 接口基址

| 服务 | 基址 | 前缀 |
| --- | --- | --- |
| 业务后端 | `http://<host>:8000/api/v1` | 前端 `VITE_API_BASE_URL` |
| 管理端 | `http://<host>:8000/api/v1/admin` | 全部需管理员 JWT |
| AI 引擎 | `http://<host>:8001/engine` | **仅后端调用，前端禁连** |

### 4.2 公开接口（无需 token）

以下接口前端可直接调用，详见 [WebMvcConfig.java](../packages/server-business/src/main/java/com/redtour/business/config/WebMvcConfig.java) 白名单：

- `POST /api/v1/auth/login`、`/api/v1/auth/register` 登录注册
- `GET /api/v1/health` 健康检查
- `GET /api/v1/scenic-areas/**` 景区浏览
- `GET /api/v1/spots/**` 景点浏览
- `GET /api/v1/routes/**` 路线浏览
- `GET /api/v1/products/**` 特产浏览
- `GET /api/v1/artifacts/**` 文物浏览
- `GET /api/v1/scripts/**` 剧本浏览
- `POST /api/v1/ask`、`GET /api/v1/ask/recommendations` 问答
- `POST /api/v1/pose/**` 姿态识别
- `POST /api/v1/devices/heartbeat` 设备心跳
- `/uploads/**`、`/audio/**`、`/icons/**` 静态资源

### 4.3 鉴权流程

1. 前端调 `POST /api/v1/auth/login` 拿到 `token`
2. 后续请求 Header 加：`Authorization: Bearer <token>`
3. Token 2 小时过期，过期返回 `401`，前端重新登录
4. 角色权限不足返回 `403`

### 4.4 统一响应结构

```typescript
interface ApiResponse<T> {
  code: number;      // 0 成功，非 0 错误
  message: string;
  data: T | null;
}
```

错误码：`400` 参数错误 / `401` 未授权 / `403` 无权限 / `404` 不存在 / `409` 冲突 / `500` 服务异常。

类型定义见 [public-common/api-types/index.ts](../public-common/api-types/index.ts)，前后端共用。

## 五、跨域说明

后端已全局放开 CORS，见 [CorsConfig.java](../packages/server-business/src/main/java/com/redtour/business/config/CorsConfig.java)：

- `allowedOriginPatterns("*")`：所有来源
- `allowedMethods`：GET/POST/PUT/DELETE/OPTIONS
- `allowCredentials(true)`：允许携带凭证
- `maxAge(3600)`：预检缓存 1 小时

**前端无需额外配置**，Vite dev server 直连后端即可。如果遇到跨域错误，检查后端是否真的启动了。

## 六、数据同步约定（重要）

### 6.1 schema.sql 维护规则

- **杨弋伽（YYJ）统一维护** schema.sql，其他成员**不要改**
- 其他人有表需求 → 提给 YYJ，由 YYJ 改 schema.sql
- YYJ 改完后推到 dev 分支，其他人 `git pull`

### 6.2 拉到新 schema 后的操作

```bash
# 1. 拉代码
git checkout dev && git pull origin dev

# 2. 重新执行 schema.sql（会 DROP 重建，清空旧数据）
mysql -u root -p < packages/server-business/src/main/resources/db/schema.sql

# 3. 重启后端，DataInitializer 会重新建 admin 账号
```

### 6.3 测试数据规则

- **只通过 schema.sql 同步**，别手动加数据
- 手动加的数据无法同步给队友，联调时 ID/数据会对不上
- 需要新的测试数据 → 提给 YYJ 加到 schema.sql

## 八、联调故障排查

### 8.1 前端请求 502 / 连不上后端

1. 确认后端在跑：`curl http://localhost:8000/api/v1/health`
2. 确认 `.env.development` 的 `VITE_API_BASE_URL` 正确
3. 改 env 后**必须重启 dev server**，Vite 不热加载 env
4. 方式 B 联调：确认后端同学机器开着、IP 没变、防火墙放行 8000

### 8.2 接口返回 401 未授权

- 公开接口返回 401：后端白名单没配，找后端同学查 [WebMvcConfig.java](../packages/server-business/src/main/java/com/redtour/business/config/WebMvcConfig.java)
- 需鉴权接口 401：前端没传 `Authorization: Bearer <token>` 或 token 过期
- 重新登录拿新 token

### 8.3 接口返回 403 无权限

- 普管访问其他景区数据：设计如此，普管只能管自己景区
- 角色不符：用 `@RequireRole({"admin"})` 标注的接口，tourist 角色访问会 403
- 检查登录时用的账号角色是否匹配

### 8.4 接口返回 500

- 看后端控制台日志，通常是 SQL 错误或空指针
- 数据库 schema 是否最新：执行 `SHOW TABLES;` 对比 18 张表
- 字段不存在：拉最新 schema.sql 重跑

### 8.5 前端跨域报错 `CORS policy`

- 后端没启动：先启动后端
- 后端版本旧：`git pull` 拉最新 [CorsConfig.java](../packages/server-business/src/main/java/com/redtour/business/config/CorsConfig.java)
- 端口对不上：确认 `VITE_API_BASE_URL` 端口是 8000

### 8.6 AI 问答返回降级提示

```
{"answer":"AI 引擎暂不可用，请稍后再试。"}
```

- 后端连不上 ai-engine:8001
- 检查 ai-engine 是否启动：`curl http://localhost:8001/engine/health`
- 检查 Ollama 是否启动：`curl http://localhost:11434/api/tags`
- **不影响其他接口**，仅问答功能降级

### 8.7 设备状态接口数据不更新

- `GET /api/v1/devices/status` 显示离线：正常，本地没树莓派
- 心跳接口需树莓派硬件脚本定时上报，开发机没有
- 联调设备相关功能需在树莓派真机或模拟心跳上报

## 九、联调流程模板

### 9.1 前后端约定新接口

1. 后端同学在 [docs/05_全局接口精简文档.md](05_全局接口精简文档.md) 登记接口（由 ZAL 统一登记）
2. 同步更新 [public-common/api-types/index.ts](../public-common/api-types/index.ts) 类型定义
3. 前端同学按类型定义调接口
4. 联调验证

### 9.2 接口字段变更

1. 后端改字段 → 同步改接口文档 + 类型定义
2. 推 dev 分支前在群里 @相关前端同学
3. 前端 `git pull` 后改业务代码

### 9.3 数据库字段变更

1. 提需求给 YYJ
2. YYJ 改 schema.sql 推 dev
3. 其他人 `git pull` 后重跑 schema.sql
4. 后端 entity/mapper 同步改

## 十、常用 curl 调试命令

```bash
# 设置后端地址变量
BASE=http://localhost:8000/api/v1

# 登录拿 token
TOKEN=$(curl -s -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 带鉴权调接口
curl -s $BASE/auth/me -H "Authorization: Bearer $TOKEN"

# 公开接口（无需 token）
curl $BASE/scenic-areas
curl "$BASE/spots?scenicAreaId=1"
curl $BASE/ask/recommendations?scenicAreaId=1

# 问答
curl -s -X POST $BASE/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"遵义会议是什么时候召开的？","scenicAreaId":1}'

# 管理端（需管理员 token）
curl -s $BASE/admin/users -H "Authorization: Bearer $TOKEN"
```
