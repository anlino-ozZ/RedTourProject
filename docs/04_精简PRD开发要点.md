# 04 产品需求文档（PRD）

> 红色文旅智能导览系统 · 开发需求文档
> 完整业务 PRD / 变更记录 / 风险表存放于外部腾讯文档，本文件为仓库内开发依据。

## 一、产品定位与背景

面向红色景区的**可离线、AI 驱动**智能导览与互动系统。系统部署在树莓派5 + Hailo8L 边缘节点上，不依赖外网即可运行全部核心功能：智能问答、姿态识别互动、导览导航、特产推荐。

### 1.1 目标场景

- 乡村红色景区（网络基础设施薄弱，4G/5G 信号不稳定或无覆盖）
- 室内红色展厅/纪念馆（需触摸屏大屏互动）
- 户外革命遗址（需移动端 H5 导览）

### 1.2 核心差异化

| 维度 | 本系统 | 传统导览系统 |
| --- | --- | --- |
| 网络依赖 | 100% 离线可用 | 需联网调用云端 API |
| 问答质量 | 基于本地史料编译的 LLM Wiki，史实可溯源 | 关键词匹配或 RAG 切片，易幻觉 |
| 互动方式 | 姿态识别（敬礼/推磨/挥手）触发讲解 | 二维码扫码或按钮点按 |
| 部署成本 | 单套约 2000 元（树莓派+Hailo+外设） | 需云服务器+带宽，月费持续 |

### 1.3 核心指标

| 维度 | 目标 |
| --- | --- |
| 技术指标 | 离线运行 100% 可用，问答响应 ≤ 3 秒 |
| 游客体验 | 平均游览时长提升 30% 以上 |
| 知识传播 | 游客历史知识测试正确率 ≥ 85% |
| 乡村经济 | 特产推荐点击率 ≥ 20%，转化率 ≥ 5% |
| 大赛目标 | 冲击国赛金奖 |

## 三、游客端功能需求（H5）

### 3.1 首页

#### 页面布局

```
┌─────────────────────────┐
│  RedNav  红色文旅导览     │  顶部导航
├─────────────────────────┤
│  [景区选择 ▼]            │  景区切换
├─────────────────────────┤
│  ┌─────┐  ┌─────┐       │
│  │ 推荐 │  │ 热门 │       │  推荐路线卡片
│  │ 路线 │  │ 路线 │       │
│  └─────┘  └─────┘       │
├─────────────────────────┤
│  智能问答入口（大按钮）    │  快速入口
├─────────────────────────┤
│  热门景点（横向滚动）      │

│  [首页][导览][问答][我的]  │  底部 Tab
└─────────────────────────┘
```

#### 业务逻辑

游客进入首页后，系统根据当前选中景区加载推荐路线和热门景点。首次访问时默认选择定位最近的景区（离线模式下使用缓存的上次选择）。推荐路线按热度与难度匹配排序，热门景点按访问量排序。

顶部景区选择器允许切换景区，切换后全站内容（路线、景点、问答上下文）同步更新。智能问答入口为全屏大按钮，点击后跳转问答页，支持语音和文字输入。

#### 字段规则

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 景区名称 | string | 当前选中景区 |
| 推荐路线 | GuideRoute[] | 最多 5 条 |
| 热门景点 | SpotInfo[] | 最多 8 条 |

#### 页面布局

路线列表页：

```
┌─────────────────────────┐
│  ← 智能导览              │
├─────────────────────────┤
│  路线列表 / 地图视图切换   │

│  路线卡片2  难度★★☆ 90min│

├─────────────────────────┤
│  [开始导览]              │  选中路线后激活
└─────────────────────────┘
```

导览进行中页：

```
┌─────────────────────────┐
│  ← 导览中  路线名称       │
├─────────────────────────┤
│  当前景点：XX纪念馆       │
│  [图片]                  │
│  [▶ 音频讲解]            │  TTS 语音播报
├─────────────────────────┤
│  进度：2/5 景点          │
│  ●●○○○                  │  景点进度指示
├─────────────────────────┤
│  [上一站]  [打卡]  [下一站]│
└─────────────────────────┘
```

#### 业务逻辑

游客从路线列表中选择一条导览路线，点击"开始导览"进入导览模式。系统按路线中的景点序列引导游客依次游览。每个景点提供图文介绍和 TTS 语音讲解，语音由 Ollama 本地模型生成或使用预录音频。

到达景点后点击"打卡"记录游览轨迹，打卡数据存储在本地（离线模式）并同步到后端（在线时）。全部景点打卡完成后，路线游览完成，触发成就解锁判定。

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路线 ID | number | 是 | GuideRoute.id |
| 当前景点序号 | number | 是 | 当前游览到第几个景点（从 0 开始） |
| 打卡状态 | boolean[] | 是 | 每个景点是否已打卡 |
| 音频 URL | string | 否 | 预录讲解音频地址 |
| 游览时长 | number | 否 | 已用时间（分钟） |

#### 状态流转

| 当前状态 | 操作 | 下一状态 | 触发条件 |
| --- | --- | --- | --- |
| 未开始 | 点击"开始导览" | 导览中 | 选中路线 |
| 导览中 | 点击"打卡" | 当前景点已打卡 | 到达景点范围内 |
| 导览中 | 点击"下一站" | 导览中（下一景点） | 当前景点已打卡 |
| 导览中 | 全部打卡完成 | 已完成 | 最后一个景点打卡 |
| 导览中 | 点击"退出" | 已退出 | 用户主动退出 |

### 3.3 智能问答

#### 页面布局

```
┌─────────────────────────┐
│  ← 智能问答              │
├─────────────────────────┤
│  对话消息列表            │
│  ┌─ 游客：长征路上...    │
│  └─ AI：遵义会议确立了... │
│                         │
├─────────────────────────┤
│  推荐问题：              │
│  [长征关键决策] [遵义会议]│
├─────────────────────────┤
│  [语音] [输入框] [发送]  │
└─────────────────────────┘
```

#### 业务逻辑

游客通过文字或语音输入问题，系统将问题透传至 AI 引擎。AI 引擎通过机架工程（Harness）处理：LocalContextMiddleware 注入当前景区上下文实现零回合定向，推理三明治生成答案，验证门核对 Wiki 引用。返回的答案附带引用的 Wiki 条目列表，前端以可点击链接形式展示，点击跳转至 Wiki 条目详情。

语音输入通过 Web Speech API 或本地 ASR 转文字。`useVoice=true` 时答案同时生成 TTS 语音播报。推荐问题根据当前景区和历史问答动态生成，离线模式下使用预设推荐问题。

响应时间目标 ≤ 3 秒（Ollama 本地推理）。

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| question | string | 是 | 用户问题，1-500 字符 |
| scenicAreaId | number | 否 | 当前景区 ID，用于上下文注入 |
| useVoice | boolean | 否 | 是否语音播报答案，默认 false |
| answer | string | - | AI 生成的回答 |
| sources | string[] | - | 引用的 Wiki 条目路径列表 |
| durationMs | number | - | 推理耗时（毫秒） |

### 3.4 沉浸式互动

#### 页面布局

```
┌─────────────────────────┐
│  ← 沉浸式互动            │
├─────────────────────────┤
│  [红色剧本杀]  [姿态互动] │  模式切换
├─────────────────────────┤
│                         │
│  摄像头预览 / 剧本场景    │
│                         │
├─────────────────────────┤
│  识别结果：敬礼          │  姿态识别反馈
│  触发讲解：军礼的由来...  │
└─────────────────────────┘
```

#### 业务逻辑

姿态互动：游客站在摄像头前做出特定动作（敬礼、推磨、挥手），YOLOv8-pose + Hailo8L 实时识别（30+ FPS），识别到目标动作且置信度 ≥ 0.85 时触发对应的讲解内容。讲解内容来自关联的 Wiki 条目，通过 TTS 语音播报。连续 3 帧识别到同一动作方触发，避免误判。

红色剧本杀：游客选择一个剧本角色，系统按剧情节点推进，游客在关键节点做出选择，不同选择导向不同剧情分支。完成剧本后根据选择路径解锁对应成就。

#### 字段规则

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| action | enum | salute(敬礼) / mill(推磨) / wave(挥手) / unknown |
| confidence | number | 置信度 0-1 |
| keypoints | number[][] | 关节点坐标数组 |
| 剧本 ID | number | 当前进行中的剧本 |
| 当前节点 | number | 剧情节点序号 |
| 已解锁成就 | Achievement[] | 本轮解锁的成就列表 |

#### 业务逻辑

空闲超时 60 秒自动返回首页。

### 4.2 语音提问

#### 业务逻辑

触摸屏端点击"语音提问"进入语音问答界面，自动开启麦克风监听。游客说话结束后（静音 1.5 秒判定结束），系统将语音转文字后送入 AI 引擎问答。答案以大字号文字展示并同时 TTS 播报。

支持"再次提问"按钮重新开始。每次问答结束后 30 秒无操作返回首页。

### 4.3 姿态互动

#### 业务逻辑

触摸屏端点击"姿态互动"进入摄像头预览界面，屏幕实时显示游客姿态骨架叠加。当识别到目标动作（敬礼/推磨/挥手）且置信度 ≥ 0.85 时，全屏展示触发效果并播放对应讲解。讲解结束后自动回到姿态检测界面。

屏幕底部展示三个动作示意图和当前识别状态。

**姿态成就领取机制：** 若本次动作触发了姿态类成就（Achievement.trigger_type=pose），在特效展示页右下角额外展示一个有效期 5 分钟的临时二维码。游客用 H5 账号扫描后，系统将解锁该成就并写入 `UserAchievement.unlocked_at`，同时在游客端"成就徽章"立即高亮显示。

### 4.4 快捷信息

#### 业务逻辑

快捷信息页以大卡片展示当前景区的核心信息：景区简介、开放时间、参观路线推荐、便民设施位置。内容只读，不支持交互编辑。点击任意卡片可展开详情。

## 五、管理端功能需求（Admin）

### 5.1 用户管理

#### 页面布局

管理端采用 Element Plus `el-container` 布局，左侧 `el-menu` 导航 + 顶部 `RedNav`。

```
┌────────┬───────────────────────────┐
│ 导航    │  用户管理                  │
│ ├用户   │  [新增] [搜索: ____] [角色▼]│
│ ├景区   │  ┌─────┬──────┬────────┐  │
│ ├景点   │  │用户名│角色  │操作     │  │
│ ├路线   │  ├─────┼──────┼────────┤  │
│ ├知识库 │  │admin│超管  │编辑/删除│  │
│ ├问答   │  │user1│普管  │编辑/删除│  │
│ ├剧本   │  └─────┴──────┴────────┘  │
│ ├文物   │  分页组件                 │
│ ├分析   │                           │
│ └设备   │                           │
```

#### 业务逻辑

用户管理仅超管可访问。支持新增、编辑、删除、搜索用户。新增用户时需指定角色和管辖景区（普管必选景区）。用户密码使用 BCrypt 加密存储。

搜索支持按用户名模糊匹配和角色筛选。删除操作为软删除，保留数据完整性。

#### 字段规则

| 字段 | 类型 | 必填 | 长度/范围 | 说明 |
| --- | --- | --- | --- | --- |
| 用户名 | string | 是 | 3-20 字符 | 字母数字下划线 |
| 密码 | string | 新增必填 | 6-32 字符 | 编辑时留空表示不修改 |
| 昵称 | string | 否 | 1-20 字符 | 显示名称 |
| 角色 | enum | 是 | - | super_admin / admin |
| 管辖景区 | number | 普管必选 | - | 普管必须指定一个景区 |

### 5.2 景区/景点/路线管理

#### 业务逻辑

景区管理：超管可新增/编辑/删除景区，普管仅可查看管辖景区。景区字段包括名称、简介、经纬度、地址、开放时间、封面图。

景点管理：管理端可新增/编辑/删除景点，每个景点归属一个景区。景点字段包括名称、简介、图片（多图上传）、经纬度、音频讲解 URL、关联 Wiki 条目。景点可与 Wiki 条目关联，关联后问答和导览中可引用。

路线管理：管理端可创建导览路线，路线由多个景点按序组成。路线字段包括名称、描述、景点序列、预计时长、难度等级。路线景点序列可拖拽排序。

打卡点管理：每个景点可设置打卡点（经纬度 + 半径），游客到达打卡点范围内方可打卡。

#### 字段规则

景区：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | string | 是 | 1-50 字符 |
| 简介 | string | 否 | 最多 500 字符 |
| 经度 | number | 是 | -180 ~ 180 |
| 纬度 | number | 是 | -90 ~ 90 |
| 地址 | string | 否 | 详细地址 |
| 开放时间 | string | 否 | 如 "08:00-17:00" |
| 封面图 | string | 否 | 图片 URL |

景点：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | string | 是 | 1-50 字符 |
| 简介 | string | 是 | 1-1000 字符 |
| 图片 | string[] | 否 | 图片 URL 数组 |
| 经度 | number | 否 | -180 ~ 180 |
| 纬度 | number | 否 | -90 ~ 90 |
| 音频 URL | string | 否 | 预录讲解音频 |
| Wiki 引用 | string | 否 | 关联 Wiki 条目路径 |
| 景区 ID | number | 是 | 归属景区 |

路线：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | string | 是 | 1-50 字符 |
| 描述 | string | 否 | 最多 200 字符 |
| 景点序列 | number[] | 是 | 景点 ID 有序数组，至少 2 个 |
| 预计时长 | number | 是 | 分钟，10-480 |
| 难度 | enum | 否 | easy / medium / hard |

### 5.3 知识库管理

#### 业务逻辑

知识库管理是 AI 问答质量的核心。管理员可录入史料素材（文本/文档上传），系统将素材编译为结构化 LLM Wiki Markdown 百科。编译过程包括：素材解析、实体抽取、Wiki 条目生成、`[[wiki-links]]` 互联建立。

Wiki 条目以文件系统形式存储（纯 Markdown 文件），适配树莓派离线环境。每个条目有标题、正文、分类标签、引用关系。管理员可编辑条目内容、查看引用关系图、重新编译。

#### 状态流转

| 当前状态 | 操作 | 下一状态 | 触发条件 |
| --- | --- | --- | --- |
| 待编译 | 点击"编译" | 编译中 | 管理员触发 |
| 编译中 | 编译完成 | 已完成 | 素材解析成功 |
| 编译中 | 编译失败 | 编译失败 | 素材格式错误或内容不足 |
| 已完成 | 编辑后重新编译 | 待编译 | 内容变更 |
| 编译失败 | 修正后重新编译 | 编译中 | 管理员触发 |

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 素材标题 | string | 是 | 1-100 字符 |
| 素材内容 | string/file | 是 | 文本内容或上传文件（.txt/.md/.docx） |
| 分类标签 | string[] | 否 | 如 ["长征","遵义会议"] |
| 编译状态 | enum | - | pending / compiling / done / failed |
| Wiki 条目路径 | string | - | 编译后生成的文件路径 |

### 5.4 问答管理

#### 业务逻辑

问答管理包括推荐问题管理和问答记录查看。

推荐问题：管理员可为每个景区预设推荐问题，展示在游客端问答页的推荐区域。每个推荐问题包含问题文本和所属景区，支持排序权重设置。

问答记录：查看游客的问答历史（脱敏），可用于分析游客关注点和优化 Wiki 内容。支持按景区、时间范围、关键词筛选。问答记录仅查看不可编辑。

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 推荐问题 | string | 是 | 1-200 字符 |
| 景区 ID | number | 是 | 所属景区 |
| 排序权重 | number | 否 | 默认 0，越大越靠前 |

### 5.5 故事/剧本管理

#### 业务逻辑

管理员可创建红色剧本杀剧本。剧本由多个剧情节点组成，每个节点包含场景描述、选项列表和跳转目标。游客在节点做出选择后跳转到对应下一节点。

剧本字段包括：剧本名称、简介、封面图、角色列表、剧情节点树。角色包含名称、头像、技能描述。剧情节点包含：节点 ID、场景文本、选项列表（选项文本 + 跳转节点 ID + 成就触发）。

完成剧本后根据游客选择路径解锁对应成就。

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 剧本名称 | string | 是 | 1-50 字符 |
| 简介 | string | 否 | 最多 200 字符 |
| 封面图 | string | 否 | 图片 URL |
| 角色列表 | Role[] | 是 | 至少 1 个角色 |
| 剧情节点 | ScriptNode[] | 是 | 至少 3 个节点 |
| 可解锁成就 | Achievement[] | 否 | 完成剧本可解锁的成就 |

### 5.6 文物管理

#### 业务逻辑

管理员可管理景区文物信息。每件文物归属一个品类（如武器、文献、生活用品），品类可关联 Wiki 条目。文物字段包括：名称、年代、简介、图片、出土/收藏地点、关联品类、关联 Wiki 条目。

游客端在导览或问答中浏览到文物时，可查看文物详情和关联的 Wiki 知识。

#### 字段规则

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | string | 是 | 1-100 字符 |
| 年代 | string | 否 | 如 "1935年" |
| 简介 | string | 是 | 1-500 字符 |
| 图片 | string[] | 否 | 图片 URL 数组 |
| 出土/收藏地点 | string | 否 | 1-100 字符 |
| 品类 | string | 否 | 如 "武器" / "文献" |
| Wiki 引用 | string | 否 | 关联 Wiki 条目路径 |

### 5.7 用户分析

#### 业务逻辑

用户分析面板展示景区运营数据，包括：游客访问趋势（折线图）、热门景点排行（柱状图）、热门问题词云、特产点击率。数据按时间范围（今日/本周/本月）和景区筛选。

超管可查看全部景区数据，普管仅查看管辖景区。数据由后端定时聚合，缓存至 Redis，前端通过 ECharts 渲染图表。

### 5.8 设备管理

#### 业务逻辑

设备管理展示树莓派及外设的运行状态：CPU 温度、内存占用、磁盘空间、Hailo8L 状态、摄像头/音箱连接状态。设备心跳每 30 秒上报后端，超过 2 分钟未上报判定为离线。

超管可查看全部设备，普管仅查看管辖景区设备。支持远程重启指令（通过 TCP 通信下发至树莓派）。

## 七、非功能需求

### 7.1 性能

| 指标 | 目标值 |
| --- | --- |
| AI 问答响应 | ≤ 3 秒（Ollama 本地推理） |
| 姿态识别帧率 | ≥ 30 FPS（Hailo8L 加速） |
| API 接口响应 | ≤ 200ms（不含 AI 透传） |
| 前端首屏加载 | ≤ 2 秒（局域网静态资源） |
| TTS 语音生成 | ≤ 1 秒（本地模型） |

### 7.2 可用性

- 离线模式 100% 可运行：AI 引擎、硬件脚本、业务后端均部署在树莓派本地
- 前端构建产物（dist/）由树莓派 Nginx 静态托管，断网可访问
- 数据库 MySQL 和缓存 Redis 部署在边缘节点，不依赖云数据库

### 7.3 安全

- 用户密码 BCrypt 加密存储
- JWT 鉴权，token 有效期 2 小时，支持续期
- 管理端接口角色校验，普管数据隔离（scenic_area_id）
- 触摸屏端无登录，仅访问公开接口
- AI 引擎和硬件 TCP 通信仅限局域网内，不暴露公网

### 7.4 兼容性

- 游客 H5：Chrome 90+ / Safari 14+ / 微信内置浏览器
- 管理端：Chrome 90+ / Edge 90+ / Firefox 88+
- 触摸屏端：Chromium kiosk 模式，分辨率 1920x1080
- 树莓派 OS：Raspberry Pi OS 64-bit (Bookworm)
