# 06 开发环境搭建清单

> 团队 5 人本地开发所需环境清单。**每人本地各搞一套**（数据库 + 后端 + 自己负责的前端），互不依赖远程服务器。

## 一、各角色环境需求总览

| 角色 | 成员 | 必装 | 选装 |
| --- | --- | --- | --- |
| 前端 | ZAL / MPH / NJY | Node 18+、npm、IDE | 本地 MySQL+Redis+后端（自给自足联调） |
| 后端 | YYJ / YST | JDK 17、Maven 3.8+、MySQL 8、Redis | - |
| AI 算法 | YST | Python 3.10+、虚拟环境 | Ollama + qwen2.5:7b（问答联调用） |
| 硬件 | MPH / YYJ | Python 3.10+、虚拟环境 | 树莓派真机（功能验证用） |

## 三、前端开发环境（ZAL / MPH / NJY）

### 3.1 安装 Node.js

```bash
# 安装 Node 18+（推荐 18 LTS 或 20 LTS）
node -v    # v18.x 以上
npm -v
```

### 3.2 启动前端 dev server

```bash
# 进入你负责的端目录
cd packages/web-h5        # 或 web-admin / web-touch

# 安装依赖（首次）
npm install

# 启动开发服务器
npm run dev
```

默认端口：

| 端 | 目录 | 端口 |
| --- | --- | --- |
| 游客 H5 | `packages/web-h5` | 5173 |
| PC 管理后台 | `packages/web-admin` | 5174 |
| 触摸屏大屏 | `packages/web-touch` | 5175 |

### 3.3 指向后端

编辑 `packages/web-xxx/.env.development`：

```bash
# 方案 A：本地自给自足（推荐）
VITE_API_BASE_URL=http://localhost:8000/api/v1

# 方案 B：指向某个后端同学的局域网 IP
VITE_API_BASE_URL=http://192.168.x.x:8000/api/v1
```

详见 `docs/07_前后端联调指南.md`。

## 四、后端开发环境（YYJ / YST）

### 4.1 安装 JDK 17

```bash
java -version    # 17 以上
```

### 4.2 安装 Maven 3.8+

```bash
mvn -v    # 3.8+
```

> 团队统一使用 settings.xml：`G:\settings\settings.xml`（私有库镜像）。
> 编译命令：`mvn -s G:\settings\settings.xml clean compile -DskipTests`

### 4.3 安装 MySQL 8.0

```bash
mysql --version    # 8.0+
```

建议配置：
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_unicode_ci`
- 端口：`3306`（默认）
- root 密码：自定，记下来待会儿填配置

### 4.4 安装 Redis

```bash
redis-server --version
redis-cli ping       # 返回 PONG 即可
```

- 端口：`6379`（默认）
- 密码：本地可不开，自定

### 4.5 初始化数据库（关键）

**首次拉代码后必须执行一次**，建库 + 18 张表 + 遵义会议纪念馆完整测试数据：

```bash
# 用 mysql 客户端执行建表脚本
mysql -u root -p < packages/server-business/src/main/resources/db/schema.sql
```

脚本特性：
- `CREATE DATABASE IF NOT EXISTS red_tour`，自动建库
- 每张表 `DROP TABLE IF EXISTS` 后重建，**重跑会清空数据**
- 用 `LAST_INSERT_ID()` 变量承接 ID，无论自增值从几开始，关联数据都对得上
- 灌入测试数据：1 景区、8 景点、3 路线、10 Wiki、20 推荐问题、8 特产、8 文物、8 成就、1 剧本、2 设备

### 4.6 修改本地配置

编辑 `packages/server-business/src/main/resources/application-dev.yml`：

```yaml
mysql:
  host: localhost
  port: 3306
  database: red_tour
  username: root
  password: 你的本机MySQL密码      # ← 改这里

redis:
  host: localhost
  port: 6379
  database: 0
  # password: 你的本机Redis密码    # 本地没设密码就注释掉
```

> **禁止提交自己的密码到仓库**，`application-dev.yml` 里保持 `root/root` 占位即可，自己本地改不改都行（反正不提交）。如果要改默认值，改本地的副本。

### 4.7 启动后端

```bash
cd packages/server-business

# 开发模式（默认 dev profile）
mvn -s G:\settings\settings.xml spring-boot:run

# 或先编译再运行
mvn -s G:\settings\settings.xml clean package -DskipTests
java -jar target/server-business.jar
```

启动后访问健康检查：<http://localhost:8000/api/v1/health>

### 4.8 自动创建的测试账号

后端启动时 [DataInitializer](../packages/server-business/src/main/java/com/redtour/business/initializer/DataInitializer.java) 会自动建三个账号：

| 用户名 | 密码 | 角色 | 用途 |
| --- | --- | --- | --- |
| `admin` | `admin123` | super_admin | 超级管理员，可操作全部景区 |
| `zunyi_admin` | `admin123` | admin | 遵义景区普管，绑定 scenicAreaId=1 |
| `test_tourist` | `123456` | tourist | 测试游客 |

## 五、AI 引擎开发环境（YST）

### 5.1 安装 Python 3.10+

```bash
python --version    # 3.10+
```

### 5.2 创建虚拟环境并装依赖

```bash
cd packages/ai-engine

# 创建虚拟环境
python -m venv venv

# 激活
# Windows PowerShell:
.\venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

# 装依赖
pip install -r requirements.txt
```

> `hailo-platform` 仅树莓派环境安装，开发机跳过。代码已做 `try-except` 降级，不影响导入。

### 5.3 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，确认 Ollama 地址、Wiki 目录路径
```

关键字段：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama 服务地址 |
| `OLLAMA_MODEL` | `qwen2.5:7b` | 默认推理模型 |
| `HAILO_ENABLED` | `false` | 开发机保持 false |
| `YOLO_WEIGHTS` | `./weights/yolov8s-pose.pt` | 权重路径，需自行下载 |

### 5.4 启动 AI 引擎

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8001
```

访问：<http://localhost:8001/engine/health>

### 5.5 安装 Ollama（可选，问答联调用）

如需联调问答功能，本机装 [Ollama](https://ollama.com/) 并拉取模型：

```bash
ollama pull qwen2.5:7b
ollama serve       # 默认监听 11434
```

> 不装 Ollama 也能跑起来 ai-engine（路由能通），但 `/engine/ask` 会返回降级提示。

## 九、常见问题

### Q1：后端启动报数据库连接失败？

- 检查 MySQL 是否启动：`mysql -u root -p` 能否登录
- 检查 `application-dev.yml` 的 `password` 是否填对
- 检查 `red_tour` 库是否存在：`SHOW DATABASES;`

### Q2：后端启动报 Redis 连接失败？

- 检查 Redis 是否启动：`redis-cli ping` 应返回 `PONG`
- Windows 装 Redis 推荐 [Memurai](https://www.memurai.com/) 或 WSL2 内跑 Redis

### Q3：前端登录接口 401？

- 检查后端是否启动：`curl http://localhost:8000/api/v1/health`
- 检查 `.env.development` 的 `VITE_API_BASE_URL` 是否指向正确后端
- 检查 [DataInitializer](../packages/server-business/src/main/java/com/redtour/business/initializer/DataInitializer.java) 是否成功创建 admin 账号（看后端启动日志）

### Q4：AI 引擎接口返回降级提示？

- `{"answer":"AI 引擎暂不可用，请稍后再试。"}` 说明后端连不上 ai-engine:8001
- 检查 ai-engine 是否启动：`curl http://localhost:8001/engine/health`
- 不影响后端启动和业务接口，仅问答功能不可用

### Q5：schema.sql 重跑后数据丢了？

- schema.sql 每张表都有 `DROP TABLE IF EXISTS`，重跑 = 重建
- **请勿在本地手动加测试数据**，否则同步时对不上
- 测试数据只通过 schema.sql 同步，schema.sql 由 YYJ 统一维护

### Q6：PowerShell 执行策略报错无法跑 Maven？

- 项目要求用 `mvn -s G:\settings\settings.xml clean compile -DskipTests`
- 团队成员若本机没装 Maven，可用 IDEA 内置 Maven + 上述 settings.xml
